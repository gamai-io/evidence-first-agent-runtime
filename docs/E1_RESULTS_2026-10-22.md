# E1 — capability widening (2026-10-22)

Defensive prototype: `polymorph/`. It does not generate malware and does not
execute the corpus; it checks a plan against a signed lease.

## Setup

- 20 benign plans: `/in` read, `/out` write, approved `api.internal`,
  `/bin/true`, `/bin/echo`, mail/chat.
- 40 malicious plans: each adds one forbidden effect: external network, shell
  exec, `/etc/passwd`, `/root/.ssh`, path escape (`/out/../etc`), external send,
  or external DB.
- Static admission: every effect and scope must be a subset of the lease.

## Results

| Host | Benign allowed | Malicious denied | Capability gain recorded | FP / FN | p50 |
|---|---:|---:|---:|---:|---:|
| Contabo | **20/20** | **40/40** | **40/40** | **0 / 0** | **0.005 ms** |
| VastVM | **20/20** | **40/40** | **40/40** | **0 / 0** | **0.009 ms** |

`polymorph/tests/run_tests.py`: **7/7** on both hosts.

Reproduce:

```bash
python3 polymorph/gen_e1.py
python3 polymorph/run_e1.py
python3 polymorph/tests/run_tests.py
```

## What this proves

- A variant that asks for a capability outside the lease is rejected before
  execution; the recorded capability gap is explicit.
- A benign variant can change order, names, paths inside scope, encoding and
  count without being rejected.
- Scope escape (`/out/../etc`) is caught statically.

## What this does not prove

- It does not prove that a variant is semantically equivalent; it proves only
  that its declared effects fit. A mutant with the same effects but different
  behavior is a different program and needs output/evidence checks.
- No execution isolation was tested here. That is gVisor/Firecracker/PROTEAN.
- The corpus is small and authored by us; not an adaptive attacker.
