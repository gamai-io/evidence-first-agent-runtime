# E3 — cross-language holdout (2026-10-22)

Question: does the v2 lexical detector generalize to a language it was not
tuned on? Corpus: 30 human-authored German attacks (5 classes) + 15 German
benign tasks. No German strings were added to the lexicon before this run.

## Result

| Metric | Result |
|---|---:|
| German attacks blocked | **1/30 = 3.33%** |
| German benign false positives | **0/15** |
| Only blocked attack | `DROP TABLE` tool injection |

Every other class was missed with score **0.0**: instruction override, role
impersonation, secrecy, memory persistence and prompt exfiltration.

## Interpretation

This is the honest generalization gap. The v2 lexicon is English/Bosnian
specific; the only German attack blocked was blocked by a language-neutral
SQL token (`DROP TABLE`). A tuned 100% result does not transfer across a
language boundary.

This is exactly why the plan separates **filter** from **boundary**:

- the lexical filter is a cheap, fast first line, not a security boundary;
- the capability lease / effect typing / evidence chain is the boundary and is
  language-independent;
- the next fix for the filter is a multilingual embedding/translation layer or
  a model-authored holdout, not another regex per language.

## Reproduce

```bash
python3 polymorph/e3_cross_language.py
```

Artifacts: `polymorph/corpus/e3_de.jsonl`, `polymorph/corpus/e3_results.json`.
Run on Contabo; same corpus is transferable to VastVM/Linux3.

## What not to do

Do not quote the tuned 100% as cross-language protection. Do not add German
regexes and call it generalization; that would be another tuned corpus. Measure
on a language you did not use for tuning.
